# Agent Notes: NanoKVM Pro Desk Screen

Standard: ha-standards v0.5.2

Language: README in **English**; code, logs and `strings.json` in English; translations en + pt-BR.

## Overview

Local polling integration for the front-panel screen of a Sipeed NanoKVM Pro Desk. A small root
agent runs on the Desk (`/userapp/nanokvm-desk-agent`, systemd) and serves the framebuffer and
input over token-protected HTTP. Home Assistant installs and manages that agent over SSH from an
admin-only sidebar panel. Read SECURITY.md before changing anything on the agent side.

## Code structure

All code in `custom_components/nanokvm_pro_desk_screen/`.

- `__init__.py`: builds the `DeskAgentClient` and coordinator (stored in `entry.runtime_data`), registers static files, HTTP views and the sidebar panel (one panel listing every loaded entry).
- `coordinator.py`: polls `/api/health` every 15 s; the agent hash doubles as the reachability check. `DeskScreenConfigEntry` type.
- `entity.py`: base entity, one device per entry.
- `binary_sensor.py` (agent installed, always available) and `camera.py` (snapshot JPEG).
- `views.py`: admin-only HTTP views used by the panel (resources, input, agent lifecycle with SSH host-key confirmation).
- `agent/`: `client.py` (HA side), `installer.py` + `ssh.py` (paramiko lifecycle), `runtime.py` (the code that runs **on the Desk**, stdlib only).
- `frontend/`: the sidebar panel JS.
- `diagnostics.py`: entry data with token and SSH host key redacted.

## Key concepts

- Setup succeeds without the agent: it is installed from the panel afterwards, so `async_refresh`, not `first_refresh`.
- The token is generated by the installer and saved with `async_update_entry`; the update listener reloads the entry.
- SSH passwords are never stored; host keys are pinned after the user confirms the fingerprint.

## Local validation (before push)

The pre-commit hook (`.githooks/pre-commit`) runs ruff, mypy, Pyright and pytest. By hand:

```bash
python -m ruff check custom_components/nanokvm_pro_desk_screen tests
python -m coverage run -m pytest -q && python -m coverage report
```

Deploy to ha-test: VS Code tasks in `.vscode/`.

## Deviations from standard

- `test-before-setup` / `test-before-configure` exempt: the agent does not exist until the panel installs it.
- `reauthentication-flow` exempt: the token is machine-provisioned.
